Administrators find the package under **Settings > Advanced > Cache tags**, with three tabs: **Changes**, **Purge** and **Targets**. Every document and media item also gets a **Cache** box on its **Info** tab.

## Changes

<Frame caption="A publish of Harbour mornings, with its keys, the server that applied it, and its two purges.">
![Changes, with a publish of Harbour mornings open: its keys, the server that applied it, and its two purges to the nextjs target](../screenshots/changes.png)
</Frame>

Changes lists the latest changes, newest first. Open one to see its keys, the servers that applied it, and each purge with any error.

| Status | Means |
| --- | --- |
| **Waiting for servers** | A server has not applied the change yet. |
| **Waiting for index** | Every server has applied it, but a server's index has not caught up. |
| **Purged** | Its purges are queued or sent. |

The view refreshes itself until the change is purged. [How a purge is timed](/timing) explains each stage.

:::note
Purges that ran out of attempts are listed at the top until you act on them. **Send again** once the target is back, or **Set aside** to hide one.
:::

## Purge

<Frame caption="Two keys typed in: an item's own key and a site's x- key.">
![Purge, with content-e0000000-0000-0000-0000-000000000003 and x-dictionary-en-us typed in, a Purge 2 keys button, and Purge everything below](../screenshots/purge.png)
</Frame>

Purge keys by hand, one per line. You can purge your own `x-` keys, items' `content-` and `media-` keys, a stored set's `set-` key copied from a response's header, and `umbraco` for everything. Purging an item's key purges its type's listings too, so a long listing that shows the item is reached. A script or deploy step can do the same through the [Management API](/management-api).

:::caution
After **Purge everything**, every cached response is fetched again from Umbraco, so expect more load for a while.
:::

## Targets

<Frame caption="The sample's Next.js webhook, from appsettings.json, so it is read-only here.">
![Targets, listing the nextjs webhook to http://localhost:3000/api/cache-tags, enabled, from appsettings](../screenshots/targets.png)
</Frame>

The tab lists every target, those from `appsettings.json` too, read-only. **Add target** opens the form below. Edit, test, disable or remove a target you added here at any time.

<Frame caption="A new webhook target, with its signing secret read from configuration.">
![New target form: name vercel, type Webhook, enabled, URL https://www.example.com/api/cache-tags, signing secret read from CacheTags:Secrets:VercelSecret, request headers, and Save, Send test purge and Cancel](../screenshots/target-editor.png)
</Frame>

**Send test purge** checks the target answers before you save. Keep secrets under `CacheTags:Secrets` in the site's configuration rather than typing them in. See [Purge targets](/targets#in-the-backoffice).

## The Info tab

<Frame caption="The Cache box on Harbour mornings' Info tab.">
![The Cache box: the item's key content-e0000000-0000-0000-0000-000000000003 and a Purge button](../screenshots/info.png)
</Frame>

A document's or media item's **Info** tab has a **Cache** box with the item's key and a **Purge** button. Publishing or purging the item refreshes every cached page that shows it. When the item is in [key sets](/keys#limits), the box says how many it also purges.
