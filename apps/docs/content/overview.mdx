Cache Tags lets a headless frontend cache Umbraco Delivery API responses for as long as it likes, and purges exactly the right ones when an editor publishes.

- **Exact purges.** Publishing an article purges only the responses that showed it, such as its page, the listings it appears in and the pages that pick it.
- **No stale refetch.** A purge goes out only once every delivery server serves the new content, and listings only once every server's index has it. A frontend that refetches at once gets the new version, not the old one again.
- **Your frontend decides how to cache.** The keys work with Next.js `cacheTag` and `revalidateTag`, with a CDN that purges by tag such as Cloudflare, or with anything that can receive a signed webhook.

## How it fits together

<Steps>
<Step title="The frontend fetches">

A response from the Delivery API carries the keys of everything it shows:

```http
GET /umbraco/delivery/api/v2/content/item/articles/harbour-mornings/

X-Umbraco-Cache-Keys: umbraco, content-e0000000-0000-0000-0000-000000000003
```

</Step>
<Step title="The frontend caches">

It stores the response for as long as it likes, tagged with those keys.

</Step>
<Step title="An editor publishes">

The package records the change and plans which keys it touches.

</Step>
<Step title="Every server catches up">

Each Umbraco server applies the change and acknowledges it. The package waits for all of them.

</Step>
<Step title="The package purges">

It sends the keys to each purge target: a signed webhook to your frontend, or Cloudflare's purge API. The frontend expires the tagged entries, and the next request renders the new content.

</Step>
</Steps>

:::note
Listings, such as an article list or a search, come from each server's Delivery API index, which Umbraco updates a moment after the change. The package purges them a second time once every server's index has it. See [How a purge is timed](/timing).
:::

## Requirements

| | |
| --- | --- |
| **Umbraco** | CMS 17.4 or later, Umbraco 18 included, on .NET 10, with the Delivery API enabled. |
| **Database** | SQL Server, or SQLite for a single server. Every Umbraco server, delivery servers included, needs write access to the package's tables. |
| **Frontend or CDN** | Anything that can tag its cache entries and purge by tag. The [Next.js guide](/nextjs) has a complete receiver. |

Call the Delivery API from your frontend's server, not from browsers. See [Go live](/go-live#call-the-delivery-api-from-your-server).
