---
title: Management API
description: Purge keys, and list, retry or set aside purges, from a script or deploy step.
seo:
  image: /og/management-api.png
---

The backoffice's **Purge** tab and **Failed purges** list use these endpoints, and a script can too. They need a user in the Administrators group. A script signs in as an API user in that group, with a client id and secret, as for any Umbraco Management API call.

| Request | Does |
| --- | --- |
| `POST /umbraco/management/api/v1/cache-tags/purge` | Purges the keys in the JSON array body at once: `x-` keys, items' `content-` and `media-` keys, stored sets' `set-` keys, or `["umbraco"]` for everything. |
| `GET .../cache-tags/purges?state=Dead` | Lists purges in a state: `Pending`, `Sent`, `Dead` or `Discarded`. |
| `POST .../cache-tags/purges/{id}/retry` | Sends a failed or set-aside purge again. |
| `POST .../cache-tags/purges/{id}/discard` | Sets a pending or failed purge aside. |

```sh
curl -X POST https://cms.example.com/umbraco/management/api/v1/cache-tags/purge \
  -H "Authorization: Bearer <access token>" \
  -H "Content-Type: application/json" \
  -d '["x-dictionary-en-us"]'
```
